# Whole-card rows and focus motion

Home uses the shared MatrixFocusRow for favorites, the Edit favorites action and every app/SIMKL channel. It measures its own viewport after outer padding, reserves the shared focus inset, and fits an integer number of equal slots in physical pixels. A small pixel-rounding remainder stays outside the scroll viewport. Portrait-only channels retain the preferred poster size and distribute spare width through the gaps between whole cards. Mixed channels use stable equal-width slots with narrower portrait artwork centered inside them. Favorites continue scrolling beyond the visible slots; no limit is imposed on saved favorites or the Edit action.

Native focus reveal operates on TV Material cards. The existing native TV card focus scale is retained. Since beta 36, a separated rim fits inside reserved image-slot space; artwork itself remains clipped to its fitted rounded surface. Beta 40 removes the dark keyline and feathers two low-opacity light gradients outside the rim, preserving the existing 5.5dp artwork inset and 2dp gap. Only focused artwork observes the ambient color to lightly tint this halo, with no additional image sampling. This is an inexpensive sheen, not Apple's native Liquid Glass, backdrop blur, refraction or a moving shared focus layer. The duplicated translucent rim and experimental inner scaling remain removed. Image requests are remembered by source/decoded size rather than rebuilt on focus changes. Grid/list cards consume the same artwork behavior.

App banners and mini artwork use one shared composable seeded from HomeArtwork's existing bounded memory cache; only a miss schedules IO. This avoids a fallback image frame after a warm composition is recreated. Media requests use a 120ms Coil crossfade for uncached success; memory-cache hits skip the transition. The global loader/caches and slot layout remain unchanged. [Coil 2.7 transition implementation](https://github.com/coil-kt/coil/blob/2.7.0/coil-base/src/main/java/coil/transition/CrossfadeTransition.kt) defines memory-hit skipping.

Horizontal reveal is owned by each row's BringIntoViewSpec. Home's vertical reveal handles channels; one cancellable collector returns Favorites/header focus to the top instead of competing instant scroll calls. Since beta 44, snapshotFlow observes row focus inside the existing effect rather than reading it as a composition key and invalidating Home on every row change. The focused dock heading is one line so app names cannot change the dock's vertical position. Explicit Home/Back reset actions retain their reset semantics. Row reconstruction does not issue a separate offset-reset scroll.

Beta 44 removes BoxWithConstraints and one wrapper from shared artwork. A layout modifier calculates the fitted image bounds from incoming pixel constraints, measures once and centers the decorated child in the unchanged aspect-ratio slot. Geometry stays in the measurement phase, avoiding subcomposition for every recycled app/action/media card. Beta 45 also removes each row's BoxWithConstraints: Home passes its measured width after the dock's outer padding, and the shared row subtracts its own fixed outer inset before running the existing pixel-based whole-slot calculation. Home retains one responsive parent measurement. No focus, image-fit, cache or style policy is replaced. This follows Google's [layout performance guidance](https://github.com/android/skills/blob/main/jetpack-compose/jetpack-compose-performance/references/layouts.md) and [custom measurement API](https://developer.android.com/develop/ui/compose/layouts/custom).

Beta 43 preserves beta 39's immediate Home/Back reset implementation. The animated reset and attempted shared-effect reset from betas 40/41 were removed after stricter dump checks exposed an early-D-pad race. Reverting those changes alone did not fix Back: a consumed Back-to-first-card request could replay when a lazy row was recreated and steal Home focus. Rows now acknowledge that one-shot request after focusing the first card. The strict device sequence verifies independent row memory, Back to card zero, then Back to Home. No accessibility timing/permissions/default-Home policy was changed. Warm banner seeding and uncached poster fades improve artwork appearance independently of spatial reset behavior.

Beta 37 experimented with a 20% vertical focus line. Its stress measurements did not improve, so beta 38 removes that policy and its test, retaining minimum-distance reveal. Horizontal rows remain explicit focus groups with retained focus. While a vertical reveal is moving, only held-key repeat events are consumed; a fresh press and the next repeat after settling still navigate. Nothing is queued to continue moving after release. This trades repeat throughput during an animation for a stable visual target; physical remote behavior must be checked, not inferred from injected taps. No deprecated BringIntoViewSpec animation override is used.

Beta 39 uses Compose's viewport-relative LazyLayoutCacheWindow for Home only: 0.5 viewport ahead and 0.5 behind. This retains nearby composition/focus nodes across direction changes without retaining every channel. Existing 6MiB image memory/32MiB disk limits are unchanged. The trace-guided hypothesis is reduced CPU focus/layout churn, not a guaranteed frame-rate improvement. See [motion review](MOTION-REVIEW.md) for measurements and limitations.

When a wallpaper covers Home, its hidden app-color texture animation is disabled. Photo overlays, focused-artwork backgrounds without a wallpaper, and panel gradients retain their appearance. This removes unnecessary work; it is not a claim of a guaranteed frame rate.

`adb shell dumpsys activity com.matrix.launcher --matrix-ui` includes RowLayout entries: visible slot count/width, viewport, first/last visible index, partial count and scrolling state. It includes no row titles, app IDs or media URLs. After a scroll settles, run:

```powershell
python tools/check_row_layout.py --adb <adb> --serial <TV-IP>:5555
```

These tools select only the resumed activity; a stopped standard launcher task may coexist with an Android Home task and must not supply stale diagnostics. HomeViewport adds vertical first/last indices, scroll offset/state and event/repeat/deferred counters. It contains no user content. UI automation on this TCL can return a null root; activity/window metadata is the fallback.

```powershell
python tools/check_home_navigation.py --adb <adb> --serial <TV-IP>:5555 --output artifacts/motion-run
```

The bounded harness checks rapid bursts, paced Down to the final channel, rapid Up, synthetic longpress, Home reset and frame counters without screenshots, app launches or preference changes. Synthetic longpress emits a limited repeat pattern and does not simulate a continuously held real remote. `measure_navigation.py` also defaults to no screenshots (`--screenshot` is opt-in). Geometry checks do not certify optical alignment, physical-key repeats or every content/provider combination.

The implementation follows Android's current [TV scrollable-layout guidance](https://developer.android.com/training/tv/playback/compose/lists): standard lazy containers and scoped BringIntoViewSpec. [Compose performance guidance](https://developer.android.com/develop/ui/compose/performance/bestpractices) recommends stable lazy keys/content types, remembered expensive objects and deferring animation reads to layout/draw. [TV CardDefaults](https://developer.android.com/reference/kotlin/androidx/tv/material3/CardDefaults) documents outer card scaling. Apple's [focus guidance](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection/) and [materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials) informed the visual direction; native tvOS effects are not portable Android APIs.

Beta 53 separates scroll resets from Home-key routing: the scrolling harness uses explicit Matrix MAIN/HOME intents by default. Use `--home-key-reset` only for a separate synthetic-routing check; neither route certifies a physical remote. Automatic tests stop if Matrix loses foreground. See [audit validation](VALIDATION.md) for the failed injected-Home attempt and remaining jank.

Beta 55 preserves the same row geometry, repeat backpressure and identity-based focus/Back behavior. A one-viewport visited-row retention window and bounded geometry cache passed strict row-memory checks and the post-reboot real-remote test. The initially regressed nested-prefetch experiment was removed. [Measured outcomes and remaining frame spikes](OPTIMIZATION-54.md).

Version 2.5.0 unifies favorites and channel row focus memory: `focusedFavId` tracks the active favorite or action card (`favRetained`), passed as `fallback` to `MatrixFocusRow`. `focusProperties { onEnter = { if (fallback != FocusRequester.Default) fallback.requestFocus() } }` guarantees that vertical inter-row navigation targets the remembered card rather than resetting to index 0 or snapping via 2D spatial heuristics. Edge boundaries (header Up and bottom channel Down) safely cancel focus change to prevent traps and void navigation. LazyRow instances use `LazyLayoutCacheWindow(aheadFraction = 1f, behindFraction = 1f)` to retain nearby cards and prevent composition eviction.
